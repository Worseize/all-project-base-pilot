# Личные данные: где заглушки

Шаблон — бэкап узла **без личных данных**. После `git clone` систему
разворачивают на новом сервере, заменяя заглушки; реальные значения живут
вне git.

## Что обезличено

| Что | Заглушка в шаблоне |
| --- | --- |
| домен | `example.test` |
| адрес сервера | `192.0.2.10` (TEST-NET-1) |
| домашние пути | `/home/agent`, `/srv/<id>` |
| имя владельца | `owner`, `OWNER_ID` |
| имена репозиториев | `<owner>/<repo>` |
| имена агентов | `template-agent`, `bot-agent`, `portfolio-agent` |
| почта | `*@example.invalid` |

## Что и где заполняется

| Место | Что заменить |
| --- | --- |
| `PROJECT.md` | назначение, стек, домены, границы |
| `project.json` | имя, версия, дата, команды, CI |
| `deploy/systemd/*.service` | пути, пользователи, лимиты |
| Caddy-блоки (`deploy/site-config.sh`) | домены и адреса бэкенда |
| `deploy/mailbox-rules.json` (вне git) | пути агентов, каналы |
| `~/.secrets`, `/etc/owner-desk` | токены, пароли, ключи |
| `~/.ssh`, `keys/` | публичные ключи агентов |
| `projects.json` | реальные id, домены, порты |

## Порядок

1. `git clone` шаблона на новый сервер.
2. Заполнить таблицу выше; секреты — сразу вне git.
3. `python verify.py` — зелёный (в том числе `personal-data`).
4. Установить юниты и таймеры, включить.
5. Сгенерировать Caddy-блоки, перезагрузить Caddy.
6. Проверить сайты и шину: health, почта, расписания.

## Проверка утечки

`deploy/check-personal-data.py` сканирует текст шаблона: реальный IPv4
(кроме `127.*`, `0.0.0.0`, `255.*`, TEST-NET), почта вне
`example.*`/`agents.invalid`, `/home/<имя>` вне заглушек, токены
`ghp_`/`github_pat_`/`sk-`/`xoxb-`. Гейт `verify.py` → `personal-data`.
Тест — `tests/test_personal_data.py`: заглушки проходят, реальные
значения — красный.

## Чего не копировать

`mailbox/`, `.env`, приватные ключи, снимки данных, `var/log/`. Генератор
структуры проекта не править: инструкция описывает его, но не заменяет.
