# Бэкап данных проекта ставит узел при онбординге

Узел бэкапит свои данные (`/var/lib/watchdog`) и не бэкапит каталоги данных проектов. На живом примере: после удаления старого сервера у проекта остаётся одна копия данных — на узле, без резерва.

Проект не должен решать это сам: свои таймеры и службы ему запрещены, значит бэкап — обязанность узла.

Нужно:

1. **`deploy/project-backup.sh <id>`** — снимок каталога данных проекта: `tar.gz` + `sha256`, каталог `/var/backups/<id>` с правами `0700 root`, файлы `0600`, ротация `KEEP` (по умолчанию 14). Целостность проверяется сразу: архив читается и содержит каталог проекта, иначе выход с ошибкой.
2. **Юнит и таймер `proj-backup@<id>.service` / `.timer`** — ежедневно, `Persistent=true`, случайная задержка.
3. **Онбординг ставит таймер каждому проекту** — включить `proj-backup@<id>.timer`, проверить первый запуск.
4. **Проверка восстановления** — часть онбординга: снимок разворачивается во временный каталог, считается число записей, каталог удаляется.
5. **В контракте** — «данные бэкапит узел, проект отвечает за их корректность и за то, чтобы всё состояние лежало в каталоге данных».

Критерий: у каждого проекта есть активный таймер, свежий снимок, самопроверка на фикстуре; в приёмке — снимок создан, читается, восстановление даёт те же числа.
