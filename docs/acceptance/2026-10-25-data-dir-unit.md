# Юнит не даёт каталог данных; очистка приёмки удаляет общий юнит

**1. Юнит проекта не даёт каталог данных.**
`proj@<id>.service` содержит `ProtectSystem=strict` и `ReadWritePaths=/srv/%i/current`, но не объявляет каталог данных. В результате:
- проект, который правильно берёт путь из `PROJECT_DATA_DIR`, при пустой переменной пишет **в каталог кода** — ровно то, чего мы избегаем;
- если переменную задать, запись всё равно падает: `Read-only file system`, потому что каталог не в `ReadWritePaths`.

Ожидание: шаблон сам объявляет данные проекта — `StateDirectory=%i`, `Environment=PROJECT_DATA_DIR=/var/lib/%i`, `ReadWritePaths=/var/lib/%i`. Тогда проект получает writable каталог без ручных дроп-инов, а `deploy-project.sh` не оставляет данных в коде.

**2. Очистка приёмки удаляет общий юнит.**
`deploy/ci/isolation-cleanup.sh` удаляет `/etc/systemd/system/proj@.service` — общий шаблон, который нужен **всем** проектам. После прогона приёмки живые проекты остаются без файла юнита: работает только загруженная копия, а после `daemon-reload` или перезагрузки сервис не поднимется.

Ожидание: очистка удаляет только экземпляры (`systemctl disable proj@<id>`, каталоги, ключи), а общий шаблон не трогает. Проверка в CI: после прогона приёмки `proj@.service` на месте.

Критерий: проект после онбординга пишет данные в `/var/lib/<id>` без ручных дроп-инов; после прогона приёмки шаблон юнита существует.
