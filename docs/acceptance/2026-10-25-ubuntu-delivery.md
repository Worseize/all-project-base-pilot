# Доставка кода проекта сломана на Ubuntu 24.04; CI гоняет другую ОС

**1. Онбординг падает на Ubuntu 24.04 (git 2.43).**
После установки baseline и запуска онбординга проекта bootstrap завершается с кодом 128:

```
fatal: detected dubious ownership in repository at '<корень>/<id>/repo.git'
fatal: Could not read from remote repository.
```

Каталог рабочей копии не создаётся, проект остаётся с одним bare-репозиторием. Причина: клонирование выполняется от root, а репозиторий уже принадлежит пользователю проекта; `git -c safe.directory=...` для `clone` не помогает — этот параметр учитывается только из системного или глобального конфига, а не из `-c`.

Проверка фикса: клонирование от имени пользователя проекта проходит без ошибок. Значит правильный путь — выполнять клон через `runuser -u <id>` (каталог и так принадлежит проекту), а не от root с `-c`.

**2. CI этого не видит, потому что гоняет не ту ОС.**
Workflow использует `ubuntu-latest`, а он уже переехал на Ubuntu 26 с более новым git. На документированной цели (Ubuntu 24.04) дефект воспроизводится, в CI — нет.

Ожидание: CI фиксирует версию (`ubuntu-24.04`) или матрицу 24.04 + latest, чтобы целевая ОС проверялась явно.

**3. Доставка происходит только при онбординге.**
Хук `post-receive` для проекта не ставится: в каталоге хуков только `pre-receive`. Поэтому после перевода `main` рабочий каталог не обновляется, и задеплоить принятую правку нечем — код остаётся в bare-репозитории.

Ожидание: при обновлении `main` код появляется в рабочем каталоге проекта (checkout от имени проекта), и юнит можно перезапустить; либо документация честно называет это отдельным шагом, и тогда шаг должен быть скриптом с проверкой.

Критерий: на Ubuntu 24.04 последовательность «baseline → проект → push в review → main → правка видна в рабочем каталоге» проходит целиком, и CI это проверяет на той же версии ОС.
