# Один сторож на узле: health.sh проекта вместо своего процесса

Сейчас у проекта свой сторож: отдельный процесс, свой канал в Telegram, свои проверки. У узла тоже есть сторож. Два сторожа дают два канала, дубли алертов и два места, где хранится токен.

Нужно разделить ответственность:

**1. Проект знает, что значит «здоров».**
Проект поставляет исполняемый `health`, который завершается кодом 0 (здоров) или 1 (болен) и печатает одну строку причины. Что проверять — решает проект.

**2. Узел запускает проверку и шлёт алерт.**
Узел раз в минуту запускает `health` каждого проекта из реестра, от пользователя проекта, с таймаутом. Красный результат — сообщение в общий канал с именем проекта и причиной. Повторы подавляются по времени.

**3. Своего сторожа-процесса у проекта нет.**
Отдельный процесс сторожа убирается: проверки переезжают в `health`, отправка — на узел.

Требования:
- `health` обязателен; отсутствие — ошибка конфигурации, а не «здоров»;
- таймаут и код возврата важнее текста: сообщение — одна строка;
- проверка не требует root;
- в журнале узла видно: проект, время, результат, причина;
- восстановление (было 1 → стало 0) — одно сообщение.

Критерий: проект без своего сторожа получает алерт при сломанном `health`; здоровый молчит; повторы подавлены; после исправления — «восстановлен».
