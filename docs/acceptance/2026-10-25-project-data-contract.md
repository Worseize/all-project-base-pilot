# Контракт проекта: режим файлов, PROJECT_DATA_DIR, процессы, сайт, журналы

Контракт (`docs/AGENT-CONTRACT.md`) покрывает: обязательные файлы, секреты, данные «в общем виде», push и запреты. Живой проект показал, что этого мало — пять вопросов он задал, и ответов в контракте не было.

**1. Режим файлов.** `run` и `test.sh` должны быть исполняемыми **в git** (`100755`). На Windows режим не сохраняется, и проект приезжает с `100644`: гейт ещё проходит, а служба не стартует. В контракт — требование, в гейт — проверка режима с понятным сообщением.

**2. Имя переменной данных.** Контракт говорит «путь задаёт администратор», но не называет переменную. Проекту нужна точная: `PROJECT_DATA_DIR`. Плюс два требования:
- **всё состояние** проекта — под этим каталогом (иначе бэкап узла его не увидит);
- `test.sh` зелёный в **чистом клоне с пустым каталогом данных**. Это ловит связку «тесты требуют данные из репозитория» — самый частый способ провалить приёмку.

**3. Несколько процессов.** `run` — единственная точка запуска, но может поднимать дочерние процессы и следить за ними: узел видит один процесс. Если у проекта несколько процессов и общие файлы — блокировки (один писатель или файловый замок) его ответственность; узел это не проверяет.

**4. Сайт.** У проекта может быть статика. Нужно описать, как он её объявляет: домены, корень, редиректы; конфиг обратного прокси делает узел, проект его не правит. Сейчас про сайт в контракте нет ничего, и это выясняется только перепиской.

**5. Журналы.** Системный вывод (`stdout`/`stderr`) уходит в журнал узла; собственные журналы проекта — внутри каталога данных, со своей ротацией; писать в системные каталоги нельзя.

**6. Бюджет проверки.** Быстрый набор в гейте — до пары минут; полный — отдельно. В тестах нет сети и настоящих секретов, в рабочие журналы тесты не пишут.

Критерий: проект, прочитавший только контракт и скелет, проходит приёмку без единого вопроса. Проверка — в CI шаблона: пробный проект на Python проходит путь «скелет → правки → push → гейт зелёный», и отдельно — негативные случаи (нет exec-бита, тесты требуют данные, сайт не объявлен).
