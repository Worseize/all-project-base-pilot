# Хук приёма ломает проект из скелета: verify.py, protected-пути, allowlist

Проект, заведённый из скелета, не может запушить: хук отказывает по трём причинам.

1. **Гейт берётся из `main` как `verify.py`.** В скелете его нет, поэтому приём падает с «cannot load trusted verify.py from main». Для проекта гейт — это его собственный `test.sh`, и он тоже должен браться из `main`, а не из пушимого дерева.
2. **Список защищённых путей жёстко зашит и совпадает с раскладкой узла.** Он запрещает `tests/`, `deploy/`, `cmd/`, `project.json` — но у проекта это его собственные каталоги: тесты и его скрипты. В итоге любой нормальный пуш отклоняется как «gate files changed».
3. **Allowlist путей по умолчанию содержит один каталог** (`app/`), а проект живёт в корне репозитория. Без ручной правки он не может запушить ни один файл.

Ожидание:
- гейт проекта — исполняемый `test.sh` из `main`; если его нет — отказ с внятным сообщением;
- защищённые пути задаются для проекта отдельно и по умолчанию пусты (репозиторий проекта — это его репозиторий);
- allowlist умеет «разрешено всё» (`*`) и по умолчанию для проекта именно так; смысл allowlist — ограничивать проект, который делит репозиторий с узлом, а не проект в своём репозитории.

Критерий: проект из скелета пушит в `review` без ручной правки хуков; пуш с изменённым `verify.py` по-прежнему отклоняется там, где этот файл есть; отсутствие `test.sh` даёт понятный отказ.
