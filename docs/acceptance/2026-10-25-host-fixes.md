# Три дефекта: дубль logrotate, ложный сирота, нет доставки кода проекта

Проверено прогоном на чистом Ubuntu 24.04: установка узла, онбординг двух проектов, push, гейт, канарейка.

**1. Два правила logrotate ротируют одни и те же файлы.**
`host-baseline.sh` создаёт правило на все журналы приёмки (`/var/log/git/*.log`), а `bootstrap-project.sh` — отдельное правило на каждый проект. После штатной последовательности `host-baseline` → `bootstrap-project` logrotate падает:

```
error: duplicate log entry for /var/log/git/proj-a.log
```

Ротация этого файла не выполняется вообще — журнал растёт без предела, хотя `docs/LOGGING.md` обещает 100 КБ × 5.

Ожидание: одно правило на файл. Варианты: убрать per-project правило из `bootstrap-project.sh` (baseline уже покрывает маску) или сделать baseline не ставить маску, а только каталог.

**2. `audit-drift.sh` считает любой каталог в корне проектов «сиротой».**
Проверка обходит все каталоги первого уровня и требует, чтобы каждый был в реестре. На узле, где рядом с проектами лежит что-то ещё (чекаут самого шаблона, каталог бэкапа), аудит краснеет:

```
drift: orphan-dir: <корень>/посторонний not in registry
```

Ожидание: сирота — только то, что похоже на проект (есть `repo.git` или `CANARY`), либо явный список исключений в реестре.

**3. Принятый код проекта никуда не доставляется.**
`bootstrap-project.sh` создаёт только bare-репозиторий, хуки, ключ и юнит. Рабочего каталога проекта и шага деплоя нет, при этом юнит запускает launcher из каталога проекта. То есть после push в `review` и перевода `main` запускать нечего: файла, на который смотрит юнит, не существует.

Ожидание: после принятия `main` код появляется в рабочем каталоге проекта (checkout из bare-репозитория) и юнит может стартовать; либо документация честно говорит, что доставка — отдельный шаг администратора, и тогда она должна быть скриптом с проверкой.

Критерий: установка «baseline → проект → push → main» даёт запускаемый проект, а `audit-drift` и `logrotate -d` зелёные.
