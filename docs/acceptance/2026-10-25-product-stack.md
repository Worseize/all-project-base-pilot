# Узел не диктует язык продукта: убрать Go из политики шаблона

Проверка показала: Go в шаблоне — не только инструмент узла, но и **политика для продукта**. Если убрать из шаблона Go-файлы, гейт краснеет:

```
[FAIL] required files — go.mod, cmd/deadcode/..., cmd/schemes/..., examples/minimal-go/...
[FAIL] schemes — go: cannot find main module
```

То есть шаблон требует от администратора держать в репозитории Go-модуль и пример на Go, даже если продукта здесь нет вовсе.

Что закрепляет Go как требование:
- правило 4 сформулировано как «Пишем на Go, только стандартная библиотека»;
- в тексте правил и стратегии — «стек по умолчанию: Go»;
- список обязательных файлов включает `go.mod`, `cmd/*` и `examples/minimal-go`;
- профиль проекта описывает Go-стек, а не роль узла;
- проверка схем запускает `go` в корне репозитория и падает без модуля.

Нужно разделить два разных вопроса: **на чём написан узел** и **на чём пишут продукт**. Второй шаблон решать не должен.

Предлагаемые изменения:
1. Правило 4 переформулировать: ноль сторонних зависимостей у узла и его инструментов; стек продукта выбирает проект и фиксирует в своём профиле. Количество правил остаётся десять.
2. Из `project.json` убрать `stack: go` и продуктовые команды; оставить команды инструментов узла.
3. В обязательных файлах оставить только то, что принадлежит узлу: инструменты схем и анализа, документы, конфигурация. Пример проекта переименовать в нейтральный и не требовать его наличия.
4. `verify.py`: проверки Go применяются к инструментам узла, а не к корню; при отсутствии продукта гейт зелёный. Добавить тест-регресс «шаблон без продукта проходит гейт».
5. Документы: убрать «стек по умолчанию — Go», вместо этого — «узел не диктует язык продукта».
6. Если позже захочется убрать Go совсем — отдельный шаг: инструменты переписать, `go.mod` и `setup-go` удалить. Сейчас это не требуется.

Критерий: клон шаблона без файлов продукта проходит гейт; в документах нет утверждения, что продукт пишется на Go.
