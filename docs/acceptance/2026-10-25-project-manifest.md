# Манифест проекта: зависимости, сборка, миграции, сайт, пояс, ресурсы

Контракт описывает три точки входа, данные и секреты. Но у произвольного проекта есть ещё шесть вещей, которых в шаблоне нет вовсе — проверка документов: ноль упоминаний зависимостей, сборки, миграций, часового пояса и ресурсов.

**1. Зависимости и сборка.** Проект на Python с `requirements.txt` или на Go с `go build` сейчас просто не запустится: узел не знает, что и когда собирать.

**2. Миграции.** Проекту с базой нужен шаг «применить схему до рестарта». Без него деплой либо падает, либо поднимает новую версию на старой схеме.

**3. Сайт как механизм.** Слово «сайт» встречается в одном документе и без деталей: как проект объявляет домены, корень статики или порт приложения, кто генерирует конфиг прокси.

**4. Часовой пояс.** Проект не должен хардкодить смещение: при переезде в другой пояс напоминания и лимиты поедут.

**5. Ресурсы.** Проект знает свои потребности; узел ставит лимиты.

**6. Таймеры.** Свои cron и демоны запрещены — внутренние расписания объявляются, чтобы узел их не «оптимизировал».

Решение: файл `project.conf` в корне проекта, простой `ключ=значение`, читается узлом при онбординге и деплое; неизвестный ключ — ошибка.

Ключи: `run`, `test`, `health`, `build`, `deps`, `migrate`, `site`, `domains`, `redirects`, `port`, `memory`, `cpu`, `timezone`.

Критерий: проект с `requirements.txt` и с базой проходит «сборка → миграции → запуск»; семь сценариев в CI (нет `run`, неизвестный ключ, падение `build`, падение `migrate`, Python-зависимости, сайт с доменами, пояс) — зелёные.
