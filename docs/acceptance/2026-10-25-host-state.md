# Приёмка не должна менять хост: снимок состояния до и после

Тесты приёмки меняют состояние узла, и это не видно. Пример из жизни: очистка ставила `/srv` режим `0755` вместо базового `0711`. Проверки при этом зелёные, хост ослаблен, обнаружилось только ручным `audit-drift`.

Нужен сторож, который ловит побочные эффекты сам.

**1. Снимок состояния.** `deploy/ci/state.sh snapshot <файл>` пишет нормализованный список: режимы и владельцы `/srv`, `/srv/app`, `/var/lib`, `/var/lib/watchdog`; наличие и `sha256` шаблона `proj@.service`; список юнитов `proj@*` и `watchdog*` с `enabled/disabled`; имена в `/etc/logrotate.d`; список каталогов в `/etc/git-hooks`; отсортированные правила `ufw`; значения `sysctl` из baseline; `/etc/timezone`; наличие пользователей и групп `zz-*`, `proj-*`. Без дат, inode и размеров.

**2. Сравнение.** `state.sh diff <до> <после>` печатает различия и возвращает код 1, если они есть.

**3. Встраивание в приёмку.** В начале `isolation.sh` — снимок «до», в конце после очистки — «после», затем сравнение. Любое различие — `FAIL: приёмка изменила состояние узла`.

**4. Негативный тест обязателен.** Два сценария: обычный прогон — различий нет; подмена `chmod 0755 /srv` перед сравнением — `FAIL` со строкой про `/srv`, после сценария режим восстановить.

Критерий: `state.sh` без внешних зависимостей; сравнение в `isolation.sh`; оба сценария зелёные; на живом узле приёмка не меняет `stat -c %a /srv`.
