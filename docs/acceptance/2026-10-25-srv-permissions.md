# Очистка приёмки ослабляет /srv: 0755 вместо 0711

`deploy/ci/isolation-cleanup.sh:27` делает:

```bash
[ -d /srv ] && chmod 0755 /srv || true
```

Но базовое состояние узла — `0711 root:root` (см. `bootstrap-project.sh:51` и baseline): посторонний пользователь проходит в свой каталог, но не видит список проектов. Скрипт «восстанавливает» не тот режим, который был.

Последствие на живом узле: после любого прогона приёмки `/srv` становится world-listable, а `audit-drift.sh` справедливо пишет `[DRIFT] /srv: 755 root:root, ожидалось 711`.

Ожидание:

1. `isolation-cleanup.sh` не меняет режим `/srv` вовсе — он его не создавал.
2. Если восстановление нужно — ставить `0711`, а не `0755`.
3. В приёмке после блока очистки проверить: `stat -c %a /srv` равно `711`.
4. В `audit-drift.sh` — уже есть проверка; после прогона приёмки она должна быть зелёной.

Критерий: прогон `isolation.sh` на подготовленном хосте не меняет режим `/srv`; `stat -c %a /srv` → `711`; `audit-drift` — «дрейфа нет».
