# После merge выравнивать review на main: агент не может fetch

У агента проекта ключ только на приём: `git push`. Забрать изменения обратно (`fetch`, `clone`) он **не может** — и это правильно, ключ намеренно односторонний.

Из этого следует требование к узлу: после того как правило приняло `review` и перевело `main`, ветка `review` должна встать на тот же коммит, что `main`. Иначе следующая попытка агента запушить из своего локального состояния отклоняется как non-fast-forward, а узнать об этом и подтянуть изменения ему нечем — он не может fetch.

Наблюдаемое: после слияния `review` остался впереди `main` на служебный коммит, и следующий push из истории проекта отклонён:
```
! [rejected] HEAD -> review (fetch first)
```
Спасает только ручное выравнивание ссылки на узле.

Ожидание:
- шаг слияния (авто-правило или скрипт) переводит `main` и **выравнивает `review`** на него;
- в CI шаблона сценарий: проект пушит → правило мержит → проект пушит ещё раз из той же истории — второй пуш принимается;
- в документации сказано прямо: ключ проекта односторонний, `fetch` невозможен, состояние забирать не нужно, узел сам выравнивает ветки.
