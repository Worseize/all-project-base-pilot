# CI-джоба isolation: приёмка изоляции без ручного прогона

Сейчас изоляция проверяется вручную на одноразовом хосте. Нужна CI-джоба, которая делает то же самое на `ubuntu-latest` и краснеет при регрессиях.

Что проверять по шагам:
1. `bootstrap-project.sh` создаёт два проекта (`proj-a`, `proj-b`) с тестовым ключом.
2. Пользователь получает `git-shell`; `main` создаётся автоматически.
3. Push в `review` принимается; force push и удаление `review` отклоняются.
4. Коммит, меняющий `verify.py`, отклоняется с `gate files changed`.
5. `proj-a` не читает canary проекта `proj-b`; `sudo` у `proj-a` нет.
6. `core.hooksPath` указывает вне репозитория; журнал `/var/log/git/<proj>.log` пишется; logrotate-правило установлено.
7. В конце — очистка: пользователи удалены, каталоги и хуки убраны.

Требования: только bash и GitHub Actions, без сторонних зависимостей и без Docker; раннер `ubuntu-latest` с `sudo`. Джоба должна краснеть при возврате любой из поломок: `nologin` вместо `git-shell`, отсутствие начального `main`, ослабленный или подменяемый `verify.py`.

Критерий: workflow в `.github/workflows/`, зелёный на текущем `main`, и красный, если временно вернуть `nologin`.
