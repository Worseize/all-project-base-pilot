# Карта «правило → проверка»

У каждого правила `RULES.md` есть проверка. Правило без строки здесь не
считается обязательным. Тип `авто` — запускается гейтом, у него указан
существующий файл; `ручная` — процедура, которую агент выполняет и
подтверждает в отчёте.

| # | Правило | Проверка | Тип |
| --- | --- | --- | --- |
| 1 | Чистый код, имена и уборка | `verify.py` — gofmt, go sizes, deadcode | авто |
| 2 | Все новые фичи — в схемах | `verify.py` — schemes | авто |
| 3 | Тесты под каждую фичу | `verify.py` — commands: go test, tests/ | авто |
| 4 | Ноль сторонних зависимостей | `verify.py` — go.mod, no npm | авто |
| 5 | Схемы — источник истины | `verify.py` — schemes: SVG против документов | авто |
| 6 | Микроблоки и ООП | `verify.py` — go sizes: файл ≤ 400, функция ≤ 80 | авто |
| 7 | Читать перед записью | ручная: перед правкой открыт нужный блок целиком, в отчёте — путь и строки | ручная |
| 8 | Пять минут — стоп | ручная: обдумывание дольше пяти минут → запись «сделано / не сделано / следующий шаг» и остановка | ручная |
| 9 | Проверять живо | ручная: в отчёте живой результат (вывод команды, экран, данные, CI run), не только код возврата | ручная |
| 10 | Данные и секреты | `verify.py` — secrets, logs; `deploy/debt-check.py` | авто |

## Как проверяется сама карта

`deploy/rules-check.py`: десять строк ровно с номерами 1–10, тип
`авто`/`ручная`, у `авто` — существующий файл, у `ручной` — непустая
процедура. `verify.py` запускает его проверкой `rules-tests` и краснеет,
если правило потеряло проверку или файл исчез. Тест — `tests/test_rules_map.py`.
