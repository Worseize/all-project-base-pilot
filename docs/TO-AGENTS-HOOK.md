# Хук pre-push и подтверждение почты без запуска процессов

Аудитория: агенты bot-agent, template-agent, portfolio-agent.

## Зачем этот файл

Первая версия хука вызывала `powershell.exe`. В ограниченном песке запуск
процесса падает с `0xC0000142`, подстановка `$(...)` возвращает пусто,
`case` не совпадает — и хук делает `exit 0`, то есть **пропускает пуш**
(это называется fail-open). Из-за этого агент решил, что нужны права.

Права не нужны. Но и одного «встроенного» хука мало: чтобы отметить письма
прочитанными, обычно двигают файлы в `processed/`, а `mv` — это процесс.
Поэтому прочтение подтверждается **маркером**, а перенос делает реле.

## Как это работает

1. Агент читает `mailbox/inbox/*.md`.
2. Создаёт пустой файл `mailbox/inbox/.checked` **своим инструментом записи**
   (это не запуск процесса).
3. Реле видит маркер, переносит все письма в `mailbox/processed/`, убирает
   маркер и пишет в журнал `ACK agent=<имя> moved=<n>`.
4. Хук пускает пуш, если либо писем нет, либо есть маркер.

## Хук

`.git/hooks/pre-push`, режим 0755:

```sh
#!/bin/sh
# Почта до пуша. Только встроенные команды sh: в ограниченном песке
# нельзя запускать процессы (0xC0000142).
inbox="${GIT_DIR:-.git}/../mailbox/inbox"

if [ ! -d "$inbox" ]; then
  echo "предупреждение: нет $inbox — проверка почты пропущена"
  exit 0
fi

# подтверждение прочтения: агент создал .checked
if [ -f "$inbox/.checked" ]; then
  exit 0
fi

set -- "$inbox"/*.md
if [ -e "$1" ]; then
  echo "почта не прочитана: в $inbox есть письма"
  for f in "$@"; do
    printf '  %s\n' "${f##*/}"
  done
  echo "прочитай письма, создай $inbox/.checked и повтори push"
  exit 1
fi
exit 0
```

Всё — встроенные команды: `[ -d ]`, `[ -f ]`, `[ -e ]`, `set --`, `printf`,
`${f##*/}`. Ни `powershell`, ни `git`, ни `mv`, ни `basename`.

## Что важно знать

1. **Маркер не обманывает сам себя.** `.checked` означает «я прочитал»,
   а не «писем не было»; реле всё равно перенесёт их в `processed/`.
2. **Старое письмо видно в журнале.** Реле пишет `MAIL STALE agent=… files=…
   oldest=…min`, если письмо лежит больше часа без подтверждения. Это
   и есть сигнал, что правило не работает.
3. **Хук не «падает открытым».** Если проверку выполнить нельзя, это
   напечатано, а не скрыто.
4. **Никаких расширенных прав.** Хук читает только свой `mailbox/inbox`.

## Проверка

```sh
git push --dry-run . HEAD:refs/heads/zz-test    # есть письма, нет маркера → код 1
touch mailbox/inbox/.checked                    # или создать файл инструментом
git push --dry-run . HEAD:refs/heads/zz-test    # код 0
```

После прогона реле в `mailbox/processed/` появятся письма, а маркер исчезнет.
