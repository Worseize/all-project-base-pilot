# Зависимости

Версия 0.9.9 · 22.10.2026

Шаблон разделяет три контура. Смешивать их — главная причина спора
«почему у нас есть git, если мы за ноль зависимостей».

## 1. Продукт

То, что поставляется и работает у пользователя.

- Go, только стандартная библиотека.
- Ноль сторонних Go-модулей, ноль npm, ноль `node_modules`.
- Нет runtime-вызовов к GitHub, GitLab, Azure или другим SaaS.

## 2. Инструменты разработки

То, чем мы проверяем и собираем, но что не входит в поставку.

- Go toolchain — сборка, тесты, `gofmt`, `go vet`, deadcode, SVG-схемы.
- Python 3.11+ — `verify.py` и тесты gate.
- Git или другой VCS — история, ветки, теги. **Опционально.**

Эти инструменты не являются зависимостями продукта. Их можно заменить,
не меняя архитектуру.

## 3. Инфраструктура

То, что запускает проверки и хранит код.

- GitHub Actions, GitLab CI, Azure Pipelines — **опционально**.
- Branch protection — настройка платформы, не файл.
- Секреты CI — masked variables, не репозиторий.

По умолчанию `project.json.ci` — `["none"]`. Проект сам выбирает контур.
CI-файлы лежат как шаблоны, но не обязательны.

## Что будет без Git

- `verify.py` работает с обычной папкой; он не вызывает git.
- История — бэкапы/снапшоты; откат — копия.
- `docs/RELEASE.md` содержит git-команды только как пример для тех,
  кто использует Git.

## Что будет без CI

- `ci: ["none"]`; `verify.py` запускается локально.
- Branch protection недоступен, gate остаётся дисциплиной.
- Это допустимый режим, а не «неполный шаблон».

## Что запрещено

- Сторонние Go-модули в продукте.
- npm/Node.js в продукте.
- Секреты в коде, логах и репозитории.
- Runtime-зависимость от внешнего сервиса без ADR.

## Правило

Продукт — ноль зависимостей. Инструменты и инфраструктура — выбор проекта,
зафиксированный в `project.json`, `PROJECT.md` и ADR.
