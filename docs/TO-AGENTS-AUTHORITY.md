# Полномочия агента: когда решаешь сам, когда идёшь к узлу

Аудитория: агенты bot-agent, template-agent, portfolio-agent.

## Принцип

Всё, что входит в твой контур обязанностей, ты делаешь **без вопросов
владельцу**. Вопрос — это не осторожность, а задержка: пока ты спрашиваешь,
работа стоит. Спрашиваешь только тогда, когда действие выходит за контур
или у тебя нет прав.

## Три вопроса, чтобы понять, твой ли это контур

1. Правка внутри **твоего** репозитория?
2. Её можно **откатить** (git, бэкап, обратная команда)?
3. Она **не влияет** на другие проекты, чужие данные и общие сервисы?

Три «да» — делай сам и коротко отчитайся. Хотя бы одно «нет» — это эскалация
(ниже), а не действие.

## Что делаешь сам, не спрашивая

| Область | Примеры |
| --- | --- |
| Свой код и файлы | правки, рефакторинг, документация, тесты в своём репозитории |
| Свои проверки | `test.sh`, `verify`, линтеры, локальные скрипты |
| Свои расписания | создать, изменить интервал, переименовать (по формату `<агент>: что`) |
| Своя почта | читать `inbox`, писать в `outbox`, переносить обработанное в `processed/` |
| Свой деплой по процедуре | `push → review → гейт → main`, если гейт зелёный |
| Свои ответы узлу | `report` о сделанном, `request` о нужном |
| Мелкие правки формулировок | опечатки, ясность, ссылки — в своих файлах |

## Что требует согласования

| Область | Почему | Кто решает |
| --- | --- | --- |
| Чужой репозиторий, чужие файлы | это чужой контур | conductor |
| Общие сервисы (Caddy, systemd, сеть, DNS) | влияет на всех | conductor → владелец |
| Данные пользователей, бэкапы, восстановление | необратимо | conductor → владелец |
| Секреты, токены, доступы | безопасность | conductor → владелец |
| Деньги, домены, договоры | не техническое | владелец |
| Шаблон `all-project-base-pilot` | отдельный проект и агент | conductor через issue |
| Удаление чего-либо вне своего репозитория | необратимо | conductor |

## Порядок эскалации

```
агент → conductor (шина) → владелец (Telegram, стол решений) → обратно тем же путём
```

1. **Ты пишешь conductor**, а не владельцу. Письмо: `kind: request`,
   `topic: escalation`, `requires: none`.
2. В письме ровно четыре вещи: **что** нужно, **зачем**, **что проверишь**
   после, **к какому сроку**. Без пересказа истории.
3. **Conductor решает сам**, если это его уровень (инфраструктура, чужие
   репозитории по договорённости, порядок в шине).
4. **Если не хватает его прав** — conductor пишет владельцу в Telegram
   (стол решений: вопрос с кнопками или с вариантами) и возвращает тебе
   ответ тем же путём: `kind: decision-needed`, тот же `topic`.
5. Пока ответа нет — **не стой**: делай то, что не зависит от решения,
   и отметь в `report`, что ждёшь.

## Чего нельзя

1. Просить владельца «разрешить» то, что в твоём контуре, — это перекладывание
   работы и задержка.
2. Обходить отказ conductor через владельца или другим каналом.
3. Делать необратимое «пока никто не видит».
4. Молчать о том, что сделал: без `report` решение не считается выполненным.
5. Считать молчание ответом: нет решения — значит действие не разрешено.

## Как выглядит эскалация

```
from: portfolio-agent
to: conductor
kind: request
topic: escalation
requires: none

Нужно: домен worseize.ru указывает на новый узел.
Зачем: сайт портфолио готов, без DNS не выпустится сертификат.
Проверю: A-записи, ответ 200 снаружи, 301 для www.
Срок: до конца недели.
```

Что произойдёт: conductor проверит, сможет ли сам (DNS на узле или нет),
и либо сделает, либо отправит владельцу вопрос в Telegram с вариантами
и вернёт ответ тебе.

## Если канал сломан

Сломанная шина — не повод идти к владельцу. Это `report` conductor
с темой `bus-broken`: что именно не работает (письмо не уходит, `check.ps1`
падает, ящика нет). Канал чинит узел.
