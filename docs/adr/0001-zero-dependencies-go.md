# 0001. Go stdlib, ноль зависимостей

- **Статус:** Accepted
- **Дата:** 2026-10-18
- **Версия шаблона:** 0.6.2
- **Связанные:** RULES.md (правило 4), PROCESS.md

## Контекст

Продукт должен жить долго и собираться без сюрпризов. Критерии:
ноль сторонних зависимостей, отсутствие обновлений пакетов, отсутствие
npm-уязвимостей. JS/Node.js не подходит: npm тянет транзитивные пакеты,
регулярные обновления и CVE, которые не зависят от нашего кода.

## Решение

Пишем на Go, только стандартная библиотека. `go.mod` без сторонних
`require`, сборка с `-mod=readonly`. ООП — структуры, интерфейсы,
композиция; домен не знает про БД, HTTP и UI.

## Альтернативы

| Вариант | Почему отвергли |
| --- | --- |
| JS/Node.js | npm, транзитивные зависимости, обновления, CVE |
| Python stdlib | нужен runtime; pip-дисциплина; слабее история с одним бинарником |
| Rust std | сложнее порог входа; cargo всё равно тянет crates при нарушении дисциплины |
| Любой сторонний пакет | нарушает критерий «ноль зависимостей» |

## Последствия

- **Проще:** один статический бинарник, нет `node_modules`, `go.sum` без зависимостей.
- **Сложнее:** часть готовых библиотек недоступна; больше стандартной библиотеки.
- **Границы:** генераторы схем — build-time Python/Pillow, в продукт не входят.
- **Проверка:** `verify.py` падает на `require`, `go.sum`, npm-артефактах.
