# 0002. Red gate и журнал решений

- **Статус:** Accepted
- **Дата:** 2026-10-22
- **Версия шаблона:** 0.6.6
- **Связанные:** PROCESS.md, verify.py, .github/workflows/verify.yml

## Контекст

Правила и тесты были, но не было жёсткого перехода «красный → стоп».
Чек-лист можно пропустить; команду — нельзя. Решения при этом терялись:
код есть, а почему сделано именно так — нет.

## Решение

- `python verify.py` — единственный red gate; ненулевой код запрещает merge и деплой.
- Проверяются документы, схемы, секреты, npm/зависимости, журнал, ADR;
  при появлении `go.mod` — `go vet` и `go test`.
- CI-workflow запускает verify; branch protection требует зелёный `verify`.
- Значимые решения — в `docs/adr/`, текущие — в `JOURNAL.md`.

## Альтернативы

| Вариант | Почему отвергли |
| --- | --- |
| Ручной чек-лист | пропускается, не блокирует деплой |
| Проверка только в голове агента | нет доказательства и воспроизводимости |
| Деплой на «почти зелёном» | красный перестаёт что-либо значить |
| Тяжёлый CI с плагинами | зависимости и обслуживание ради проверки |

## Последствия

- **Проще:** красный виден одной командой; отчёт и журнал обязательны.
- **Сложнее:** нужно поддерживать verify и включать branch protection.
- **Границы:** verify — build-time Python stdlib; продукт остаётся Go stdlib.
- **Проверка:** убрать обязательный файл или добавить npm-артефакт — verify краснеет.
