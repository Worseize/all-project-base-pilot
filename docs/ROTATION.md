# Ротация сессии

Состояние живёт в репозитории, история чата — дорогой кэш. Новая сессия
стартует пустой и поднимает состояние по протоколу.

## Перед переходом

1. Почта разобрана: `inbox` пуст, ответы в `outbox`, прочтение отмечено.
2. Долги на доске честные; «не сделано» в ответе — только строки доски.
3. Работа доведена до коммита или заведена долгом; `git status` чист
   (кроме файлов, которые в git не входят).
4. Реестры обновлены: `DEBTS.md`, `docs/REQUESTS.md`, `JOURNAL.md`.

## Передача состояния

Читать в новой сессии: `AGENTS.md`, `docs/TO-AGENTS-ONBOARDING.md`,
`DEBTS.md`, `docs/WAKE-LOG.md`, `docs/REQUESTS.md`, хвост `JOURNAL.md`.

## Новая сессия

Старт по протоколу `docs/TO-AGENTS-ONBOARDING.md`; первое пробуждение по
расписанию закрывает минимум один долг (`wake-debts`).

## Быстрая проверка

В протоколе onboarding названы `deploy/front.ps1` и `deploy/check-desk.ps1` —
они есть только у узла. В шаблоне дешёвые проверки такие:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<узел>\deploy\check.ps1" -Agent template-agent
python verify.py
python deploy/debt-table.py
```

## Текст готовности

```
Готов перейти на новую сессию.

Состояние в репозитории:
- ветка <ветка> = <хеш>, незакоммиченного нет
- main не двигался: <хеш main>; работа ждёт merge у узла
- долгов: D=<n>, W=<n>, L=<n>
- почта: inbox пуст, обработанное в processed
- ожидания: <N-строки или «нет»>

Что потеряется при переходе: контекст этого чата и расписание этого чата
(расписание привязано к сессии, а не к папке).

Что сказать в новой сессии:
«Старт по протоколу docs/TO-AGENTS-ONBOARDING.md.»
Если задача продолжается — добавь строку: «продолжаем <тема>».

Таймеры переключает владелец; новое расписание опроса почты агент заводит
только себе и сообщает узлу.
```

## Проверка

`verify.py` → `rotation`: разделы на месте, протокол ссылается на
onboarding и `wake-debts`; инструкция не заменяет файлы генераторов.
