# Backup и restore

Версия 0.9.36 · 22.10.2026

Бэкап считается сделанным только после проверки восстановления.
Файл с дампом — это не бэкап, а надежда.

## Что фиксируем

| Параметр | Значение |
| --- | --- |
| Владелец данных | команда проекта, указывается в `PROJECT.md` |
| Что бэкапим | база, файлы, секреты (отдельно), конфиги |
| Частота | по критичности; минимум раз в сутки |
| Хранение | вне основного окружения, шифрование |
| RPO | сколько данных допустимо потерять |
| RTO | за сколько обязаны восстановиться |

## Процедура

1. Снять копию в изолированное хранилище.
2. Проверить целостность (размер, хеш, читаемость).
3. Восстановить на **копии**, не на проде.
4. Прогнать smoke-проверки: ключевые записи, вход, список/дерево.
5. Записать дату, версию, результат и время восстановления.
6. Удалить временную копию, если она не нужна.

## Регулярная проверка

- Раз в месяц — учебное восстановление.
- Если восстановление не проверялось — считаем бэкапа нет.
- При инциденте — сначала восстановление, потом разбор.

## Границы

`verify.py` не может проверить внешнее хранилище. Проверка — процедура
и запись в журнале; в `PROCESS.md` она относится к живой проверке.
