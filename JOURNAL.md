# Журнал решений

Одно решение — одна запись. Формат: дата, версия, решение, почему,
что отвергли, последствия, ссылки.

## 2026-10-22 · 0.9.0 · Пилот deadcode -json

**Решение:** добавили `-json` к `cmd/deadcode`, провели фичу через
правила → тест → verify → сборку → журнал.

**Почему:** нужен реальный проход по процессу, а не только self-check
шаблона. JSON нужен CI и внешним отчётам.

**Отвергли:** менять текстовый вывод; трогать AST-логику; включать
branch protection без remote (невозможно).

**Последствия:** фича готова; CI `github` выбран, но не запускался удалённо;
branch protection остаётся ручной настройкой. Пилот: 78 с до фичи,
109 с полный цикл, 0 ошибок, 0 откатов, drift обнаружен 1 раз и не пропущен.

**Ссылки:** [features/0001-deadcode-json.md](features/0001-deadcode-json.md),
[docs/PILOT.md](docs/PILOT.md).

## 2026-10-22 · 0.8.0 · Git и CI — возможность, не зависимость

**Решение:** разделили продукт, инструменты разработки и инфраструктуру
в `docs/DEPENDENCIES.md`. `project.json.ci` по умолчанию `["none"]`;
Git и CI — опциональные контуры, а не поставка.

**Почему:** «ноль зависимостей» относится к продукту, а не к Git,
Python, Pillow или CI. Смешение этих контуров создавало ложное
впечатление, что шаблон требует GitHub/GitLab/Azure.

**Отвергли:** включать все три CI по умолчанию; считать Git обязательным;
тащить Git-команды в release как безусловные.

**Последствия:** новый проект сам выбирает CI; без CI `verify.py` работает
локально; без Git история — бэкапы/снапшоты. Продукт остаётся Go stdlib.

**Ссылки:** [docs/DEPENDENCIES.md](docs/DEPENDENCIES.md),
[project.json](project.json), [docs/RELEASE.md](docs/RELEASE.md).

## 2026-10-22 · 0.7.9 · MIT License

**Решение:** поставили MIT как дефолт для шаблона.

**Почему:** MIT — простая разрешительная лицензия, которую можно
использовать в открытых и закрытых проектах; она не требует раскрывать
код проекта. Для шаблона это минимальный барьер.

**Отвергли:** Apache-2.0 — сильнее по патентам, но тяжелее для шаблона;
proprietary — ограничил бы переиспользование.

**Последствия:** файл [LICENSE](LICENSE) обязателен; при необходимости
лицензию можно заменить одним файлом и записью в журнале.

**Ссылки:** [LICENSE](LICENSE), [docs/RELEASE.md](docs/RELEASE.md).

## 2026-10-22 · 0.7.8 · Операционные процедуры

**Решение:** добавили `docs/RELEASE.md`, `docs/BACKUP.md`,
`docs/MIGRATIONS.md`, `docs/SECRETS.md` и `.env.example`. Процедуры
включены в обязательные файлы.

**Почему:** правила 8 и 10 требуют отката, бэкапа и секретов, но без
процедуры это лозунги. Release checklist фиксирует доказательства до тега.

**Отвергли:** писать скрипты бэкапа/миграций без продукта — они были бы
фиктивными; выбирать за пользователя license.

**Последствия:** `verify.py` проверяет наличие процедур, но не внешнее
хранилище и не факт восстановления. Это остаётся живой проверкой.

**Ссылки:** [docs/RELEASE.md](docs/RELEASE.md), [docs/BACKUP.md](docs/BACKUP.md),
[docs/MIGRATIONS.md](docs/MIGRATIONS.md), [docs/SECRETS.md](docs/SECRETS.md).

## 2026-10-22 · 0.7.7 · Azure DevOps и CI-список

**Решение:** добавили `azure-pipelines.yml`; `project.json.ci` стал списком
(`github`, `gitlab`, `azure`, `none`), а `verify.py` проверяет выбранные файлы.

**Почему:** «все проекты» могут жить в разных CI. Список лучше строки
`both`: можно выбрать ровно нужные контуры.

**Отвергли:** держать только `both`; считать наличие любого CI-файла
достаточным.

**Последствия:** по умолчанию включены три контура; проект может оставить
один. Branch protection остаётся настройкой платформы.

**Ссылки:** [azure-pipelines.yml](azure-pipelines.yml),
[docs/BRANCH_PROTECTION.md](docs/BRANCH_PROTECTION.md), [PROCESS.md](PROCESS.md).

## 2026-10-22 · 0.7.6 · deadcode: методы

**Решение:** `cmd/deadcode` проверяет unexported-методы. Использованием
считаются селектор `x.method`, method expression и имя метода в интерфейсе;
`// deadcode:keep` — для рефлексии и `go:linkname`.

**Почему:** методы — такая же мёртвая сложность, как функции и типы.
AST уже позволяет срез без внешних зависимостей.

**Отвергли:** полный `go/types` и автоматическое доказательство
реализации интерфейсов — это следующий уровень; сейчас консервативно
сохраняем методы, чьё имя встречается в интерфейсе.

**Последствия:** возможны false positive при вызове через рефлексию —
тогда keep. Метод с тем же именем на другом типе может скрыть мёртвый
метод (false negative); это осознанный компромисс.

**Ссылки:** [cmd/deadcode/main.go](cmd/deadcode/main.go),
[cmd/deadcode/main_test.go](cmd/deadcode/main_test.go).

## 2026-10-22 · 0.7.5 · GitLab CI и выбор контура

**Решение:** добавили `.gitlab-ci.yml`; `project.json.ci` выбирает
`github`, `gitlab`, `both` или `none`, а `verify.py` проверяет наличие
выбранного файла.

**Почему:** «все проекты» — это не только GitHub. Контур CI должен
выбираться конфигом, как стек и команды.

**Отвергли:** требовать оба CI-файла всегда; тащить GitLab-раннер
в GitHub-workflow.

**Последствия:** по умолчанию `both`; проект может удалить ненужный файл
и поставить `ci: github` или `ci: gitlab`. Branch protection остаётся
настройкой платформы.

**Ссылки:** [.gitlab-ci.yml](.gitlab-ci.yml),
[.github/workflows/verify.yml](.github/workflows/verify.yml),
[PROCESS.md](PROCESS.md).

## 2026-10-22 · 0.7.4 · deadcode: типы, переменные, константы

**Решение:** `cmd/deadcode` теперь проверяет unexported-функции, типы,
переменные и константы. Для всех — `// deadcode:keep`; generated-файлы
пропускаются.

**Почему:** функций было мало: мёртвый тип или константа так же копят
сложность. AST уже есть, расширение дешёвое.

**Отвергли:** методы — они могут реализовывать интерфейс и вызываться
через reflect; для них нужен type-check, а не только AST. Поэтому пока
не проверяем, чтобы не давать ложных красных.

**Последствия:** срез шире, но всё ещё консервативный. `// deadcode:keep`
остаётся аварийным выходом.

**Ссылки:** [cmd/deadcode/main.go](cmd/deadcode/main.go),
[cmd/deadcode/main_test.go](cmd/deadcode/main_test.go), [PROCESS.md](PROCESS.md).

## 2026-10-22 · 0.7.3 · AST-детектор мёртвого кода

**Решение:** добавили `cmd/deadcode` на `go/ast`: ищет неиспользуемые
unexported-функции, пропускает generated-файлы и `// deadcode:keep`.
`verify.py` запускает его как команду стека.

**Почему:** правило 1 требует удалять мёртвый код, но без инструмента это
держится на памяти. `staticcheck` нарушил бы правило нуля зависимостей,
поэтому инструмент свой, на stdlib.

**Отвергли:** `staticcheck`/`golangci-lint` как зависимость; полный
type-check анализ и методы — начнём с консервативного среза.

**Последствия:** инструмент ловит только unexported-функции; при
рефлексии/`go:linkname` возможен false positive — тогда `// deadcode:keep`.
Типы, переменные и методы пока не проверяются.

**Ссылки:** [cmd/deadcode/main.go](cmd/deadcode/main.go),
[PROCESS.md](PROCESS.md), [verify.py](verify.py).

## 2026-10-22 · 0.7.2 · Мультистек и #render

**Решение:** `verify.py` запускает `build/test/lint/fmt` из `project.json`
для любого стека; Go-специфичные проверки (`go.mod`, размеры Go-файлов,
`gofmt`) включаются только при `stack: "go"`. Источник схемы
`project.json#render` хеширует только version/date/fonts, поэтому смена
команд не требует перерисовки.

**Почему:** шаблон нужен на всех проектах, а не только на Go. При этом
изменение команд — не изменение картинки; drift не должен быть ложным.

**Отвергли:** хардкодить Go в gate; заставлять перерисовывать схемы при
каждой правке команд; тащить npm ради не-Go проектов.

**Последствия:** не-Go проект задаёт `stack` и `commands`, фиксирует
исключение правила 4 в ADR. Запрет npm остаётся, пока `forbid_npm`
не выключен явно.

**Ссылки:** [README.md](README.md), [project.json](project.json),
[verify.py](verify.py).

## 2026-10-22 · 0.7.1 · Secret entropy, branch protection, CI-матрица

**Решение:** secret scan дополнен `.env` и энтропией; branch protection
описан в `docs/BRANCH_PROTECTION.md`; CI гоняется на Ubuntu и Windows.

**Почему:** регулярки ловят известные форматы, но не случайные токены.
Защита ветки — единственный способ не пустить красный `verify` в `main`.
Windows-матрица проверяет, что шаблон не завязан на одну ОС.

**Отвергли:** `gitleaks`/`trufflehog` как обязательную зависимость;
надежду, что «все помнят» про branch protection.

**Последствия:** gate стал чувствительнее к случайным секретам; branch
protection всё ещё настройка репозитория, а не файл.

**Ссылки:** [docs/BRANCH_PROTECTION.md](docs/BRANCH_PROTECTION.md),
[verify.py](verify.py), [.github/workflows/verify.yml](.github/workflows/verify.yml).

## 2026-10-22 · 0.7.0 · Release candidate: профиль, конфиг, lock и тесты

**Решение:** шаблон стал конфигурируемым: `project.json` задаёт стек,
команды, обязательные файлы и схемы; `PROJECT.md` и `FEATURE.md` —
человеческие профили; `verify.py` читает конфиг. Схемы защищены
`docs/schemes.lock.json`, gate проверяется `tests/test_verify.py`,
Go-путь — `examples/minimal-go`.

**Почему:** до этого gate был захардкожен под этот репозиторий, схемы могли
устареть молча, а генераторы зависели от Windows-шрифта. На втором проекте
пришлось бы менять сам gate — это противоречит смыслу шаблона.

**Отвергли:** редактировать `verify.py` под каждый проект; хранить
обязательные ADR по именам; считать наличие PNG достаточной проверкой схем;
тихо откатываться на дефолтный шрифт.

**Последствия:** новый проект заполняет `project.json` и `PROJECT.md`,
не трогая gate. Изменение правил или стратегии требует
`python verify.py --update-schemes`. Branch protection остаётся настройкой
репозитория, а не файлом.

**Ссылки:** [README.md](README.md), [project.json](project.json),
[tests/test_verify.py](tests/test_verify.py), [docs/schemes.lock.json](docs/schemes.lock.json).

## 2026-10-22 · 0.6.7 · Практики из продуктового чек-листа

**Решение:** взяли механику, а не числа: бюджеты «файл ≤ 400 строк,
функция ≤ 80», типизированные структуры вместо map, тесты по блокам,
бэкап с проверкой восстановления, append-only миграции. `verify.py`
проверяет размеры файлов/функций и `gofmt`, когда появится Go-код.

**Почему:** эти практики уменьшают цену ошибки и не зависят от размера
команды. Они проверяемы, поэтому не остаются лозунгами.

**Отвергли:** 900 тестов / 64 группы как KPI; 71% документации как цель;
абсолютные 80/400 без контекста; Python-специфику (ruff, dict-модели) —
её заменили `go vet`, `gofmt` и типизированные структуры.

**Последствия:** правило 6 стало измеримым, правило 10 — про восстановление
и миграции, правило 3 — про разбиение тестов. Числа-ориентиры остаются
сигналом, а не целью.

**Ссылки:** [RULES.md](RULES.md) (правила 3, 6, 10), [PROCESS.md](PROCESS.md),
[STRATEGY.md](STRATEGY.md), [verify.py](verify.py).

## 2026-10-22 · 0.6.6 · Red gate и журнал решений

**Решение:** `python verify.py` — единственный red gate; деплой и merge
запрещены на ненулевом коде. Решения фиксируются в `JOURNAL.md` и `docs/adr/`.

**Почему:** правила и тесты были, но не было жёсткого перехода
«красный → стоп». Чек-лист можно пропустить, команду — нельзя.

**Отвергли:** ручной чек-лист без команды; проверку только в голове агента;
деплой «на почти зелёном».

**Последствия:** появились `PROCESS.md`, `verify.py`, CI-workflow, ADR
и журнал. Branch protection нужно включить в настройках репозитория.

**Ссылки:** [PROCESS.md](PROCESS.md), [docs/adr/0002-red-gate.md](docs/adr/0002-red-gate.md).

## 2026-10-18 · 0.6.2 · Go stdlib вместо JS/Node

**Решение:** продукт пишем на Go, только стандартная библиотека.
Сторонних модулей, npm и `node_modules` нет. ООП — структуры, интерфейсы,
композиция.

**Почему:** npm — транзитивные зависимости, регулярные обновления и CVE,
которые не зависят от нашего кода. Критерий продукта — ноль зависимостей.

**Отвергли:** JS/Node.js; Python stdlib как продуктовый рантайм;
любые сторонние пакеты.

**Последствия:** один статический бинарник; `go.mod` без `require`;
генераторы схем остаются build-time инструментами на Python/Pillow.

**Ссылки:** [docs/adr/0001-zero-dependencies-go.md](docs/adr/0001-zero-dependencies-go.md).

## 2026-10-17 · 0.5 · Десять правил и бюджет

**Решение:** держать ровно десять правил. Новое правило вбирает старое
или отклоняется.

**Почему:** иначе через месяц правил будет сорок, и их перестанут читать.

**Отвергли:** бесконечный список правил без бюджета; правила без проверки.

**Последствия:** каждое новое требование проходит через слияние с существующим
правилом; стратегия стала отдельным слоем, а не одиннадцатым правилом.

**Ссылки:** [RULES.md](RULES.md), [STRATEGY.md](STRATEGY.md).
