# Журнал решений

Одно решение — одна запись. Формат: дата, версия, решение, почему,
что отвергли, последствия, ссылки.

## 2026-10-24 · 0.9.11 · git-shell и initial main

**Решение:** пользователь проекта получает `/usr/bin/git-shell`, а не
`nologin`: git-команды проходят, интерактивного shell нет. Bootstrap сеет
`refs/heads/main` из `SOURCE_REPO`/`SOURCE_REF` (по умолчанию — HEAD
шаблона), поэтому свежий проект сразу принимает review.

**Почему:** `nologin` печатает текст в протокол git и ломает push; пустой
bare-репозиторий не даёт создать main отклонённым push.

**Отвергли:** оставить nologin и принимать первый review как main (обход
доверенного gate); требовать ручной push main.

**Последствия:** push работает; main доверенный; selftest проверяет main.

## 2026-10-24 · 0.9.10 · Канал команд и публичная приёмка

**Решение:** команды приходят только из приватного
`all-project-base-findings` (автор `conductor`, метка `from:conductor`).
В публичный репозиторий попадает только блок между `<!-- public:begin -->`
и `<!-- public:end -->` — файл `docs/acceptance/<date>-<slug>.md` с
`Версия:` и `Ссылка: findings#N`.

**Почему:** публичный issue — не команда; история должна быть файлами,
а не перепиской. Приватный контекст не утекает.

**Отвергли:** публичные issues; перенос приватного текста; ослабление
gate по команде из issue.

**Последствия:** `check_acceptance` ловит имя/дату/поля/IPv4/`/srv/`/
e-mail/`ssh-`; публичный issue не создаётся.

## 2026-10-22 · 0.9.9 · Имена и реестр проектов

**Решение:** `id` — полный токен `proj-a`; из него выводятся пользователь,
каталог, юнит, лог и поддомен. `display` — только для сообщений.
`projects.example.json` — два нейтральных проекта; `projects.json` —
рабочий реестр, в `.gitignore`. Валидатор `check_projects`, аудит
`audit-drift.sh`.

**Почему:** второе имя (короткий код, отдельный префикс) создаёт дрейф.
Публичный шаблон не должен содержать реальные имена и домены.

**Отвергли:** коммитить рабочий реестр; добавлять `display` в пути;
второй источник имени.

**Последствия:** `id` неизменяем; переименование — миграция. Тесты
проверяют id, домены, порты, status, лишние поля и `.gitignore`.

## 2026-10-22 · 0.9.9 · Изоляция: доверенный gate

**Решение:** `pre-receive` берёт `verify.py` из main; изменения gate-файлов
отклоняются; PATH включает Go; пользователь — nologin; журнал приёмки
`/var/log/git` с ACL и logrotate; selftest работает с одним проектом.

**Почему:** живая приёмка 0.9.8 показала обход gate через подмену verify.py,
skip Go, неработающую проверку портов и shell у пользователя.

**Отвергли:** доверять pushed verify.py; запрещать весь `cmd/**`; хранить
журнал в `/srv`.

**Последствия:** подмена gate и неотформатированный Go — RED; журнал
пишется и ротируется. Live-проверка — только Linux.

## 2026-10-22 · 0.9.8 · Многопроектная изоляция

**Решение:** один хост — несколько проектов; агент получает ключ только
на `git push` в `review`, хуки лежат в `/etc/git-hooks`, main двигает root
через `update-ref`, сервис — `proj@<proj>` с sandbox-лимитами.

**Почему:** нельзя пускать внешнего агента к серверу и чужим проектам.
Модель должна быть проверяемой: canary, sudo, порты, hooksPath, unit.

**Отвергли:** Docker (новая зависимость); shell/sudo агенту; общий репозиторий;
хуки внутри `repo.git/hooks`.

**Последствия:** артефакты `docs/ISOLATION.md`, `deploy/*`, ADR-0004 и
`verify.py`-проверка матрицы. Live-проверка systemd/SSH — на Linux-хосте,
не на Windows.

## 2026-10-22 · 0.9.7 · SVG-схемы на Go

**Решение:** схемы — SVG-текст, генератор `cmd/schemes` на Go stdlib.
Удалены Python-генераторы, Pillow, шрифты и `schemes.lock.json`.
`verify.py` запускает `go run ./cmd/schemes -check` и сравнивает файл.

**Почему:** это убирает build-time зависимость, а не переносит её.
SVG диффится как текст; lock с хешами источников больше не нужен.

**Отвергли:** оставить Pillow; генерировать SVG на Python; хранить PNG.

**Последствия:** схемы — текстовый outline; визуальный дизайн проще,
но источник истины и проверка сохранены.

## 2026-10-22 · 0.9.6 · Закрытый долг удаляется

**Решение:** убрали раздел «Закрытый долг» из `docs/DEBT.md`. Закрытый
долг удаляется; ссылка на решение — в `JOURNAL.md`/ADR. `check_debt`
краснеет, если секция закрытого долга осталась.

**Почему:** закрытый долг не должен попадать в контекст и создавать
впечатление открытой работы. История есть в git и журнале.

**Отвергли:** хранить закрытые долги «для истории»; помечать их
зачёркиванием; держать в отдельном файле.

**Последствия:** `DEBT.md` содержит только открытый долг; после закрытия
строка удаляется.

## 2026-10-22 · 0.9.5 · Лимиты логов

**Решение:** каждый поток — не больше 100 КБ на страницу и 5 страниц.
Страницы: `test.log`, `test.log.1..4`; `app.log`, `app.log.1..4`;
`JOURNAL.md`, `JOURNAL.1..4.md`. `check_logs` проверяет размер и количество.

**Почему:** без лимита тестовый лог и журнал растут бесконечно, а старые
записи вытесняют актуальные. 100 КБ × 5 — предсказуемый максимум.

**Отвергли:** стороннюю библиотеку ротации; безлимитный `JOURNAL.md`;
хранение логов в git.

**Последствия:** при превышении gate краснеет; ротация внешняя.

## 2026-10-22 · 0.9.4 · Логи разделены

**Решение:** `tests/test.log` — тесты, `var/log/app.log` — прод,
`JOURNAL.md` — только решения. `verify.py` проверяет разные пути
и `.gitignore`; правило 10 обновлено.

**Почему:** тесты не должны засорять рабочий журнал, а прод-ошибки —
смешиваться с тестовым шумом. Это разные потоки с разным сроком жизни.

**Отвергли:** писать всё в `JOURNAL.md`; держать тестовый лог в git;
добавлять стороннюю библиотеку логирования.

**Последствия:** `check_logs` краснеет, если пути совпадают, `JOURNAL.md`
используется как тестовый лог или логи не в `.gitignore`.

## 2026-10-22 · 0.9.3 · Close-task gate

**Решение:** добавили `verify.py --close-task`: если diff трогает
`cmd/**` или `deploy/**`, но не трогает `features/**`, `docs/adr/**`,
`docs/DEBT.md` или `JOURNAL.md` — gate красный. Добавили `docs/DEBT.md`
и шаг в CI.

**Почему:** текст в AGENTS.md и PROJECT.md — не проверка. Долг можно
забыть; close-task делает это физически невозможным на уровне пуша/PR.

**Отвергли:** проверять только AGENTS.md; требовать все четыре evidence
сразу; хранить долг в чате.

**Последствия:** код без evidence не проходит CI. `--close-task` умеет
base из GitHub/GitLab/Azure или `--base <ref>`. Тесты — unit.

**Ссылки:** [verify.py](verify.py), [docs/DEBT.md](docs/DEBT.md),
[PROCESS.md](PROCESS.md), [.github/workflows/verify.yml](.github/workflows/verify.yml).

## 2026-10-22 · 0.9.2 · AGENTS: обязательный старт и закрытие

**Решение:** в `AGENTS.md` добавлены два жёстких блока: таблица
«правило → как выполнено» до первой правки и отчёт по «Определению

**Последствия:** каждый новый сеанс обязан начать с таблицы и закончить
DoD-отчётом. Нарушение = задача не начата/не закрыта.

**Ссылки:** [AGENTS.md](AGENTS.md), [RULES.md](RULES.md).

## 2026-10-22 · 0.9.2 · PNG не хранятся в git

**Решение:** убрали `docs/scheme-*.png` из git; добавили в `.gitignore`.
`verify.py` пропускает проверку схем, если PNG нет. CI генерирует их
и проверяет drift lock.

**Почему:** PNG — генерируемый артефакт для тех, кто хочет посмотреть
картинку. Пользователю, который клонирует шаблон, он не нужен; исходники
схем — скрипты и `docs/schemes.lock.json`.

**Отвергли:** Git LFS (всё равно хранит бинарники); держать PNG только
в release-артефакте (ломает ссылки); генерировать PNG при каждом clone.

**Последствия:** clean clone проходит `verify` без PNG; схемы можно
создать командой `python verify.py --update-schemes`. CI проверяет,
что lock соответствует источникам. Репозиторий переведён в public;
branch protection включён: PR + оба `verify`-чека, force push и удаление
запрещены.

## 2026-10-22 · 0.9.1 · LF и Windows CI

**Решение:** добавили `.gitattributes` с `* text=auto eol=lf` и binary
для изображений/архивов.

**Почему:** Windows checkout с CRLF ломал хеши схем и `gofmt`; Ubuntu
проходил, Windows падал. Один и тот же коммит должен проверяться одинаково.

**Отвергли:** отключать Windows в матрице; генерировать схемы под CRLF;
чинить только workflow.

**Последствия:** текст всегда LF на всех платформах; схемы и lock
стабильны. Версия 0.9.1.

## 2026-10-22 · 0.9.1 · Hosted CI и локальный gate

**Решение:** проверили GitHub Actions на Ubuntu/Windows и локальный
серверный gate на bare-репозитории.

**Почему:** первый Windows-run упал на CRLF; после `.gitattributes`
оба job’а зелёные. Branch protection на GitHub Free private недоступен,
поэтому эквивалент проверен локально через `pre-receive`.

**Отвергли:** делать репозиторий public без согласия пользователя;
покупать GitHub Pro; считать зелёный локальный `verify.py` достаточным
доказательством серверного запрета.

**Последствия:** зелёный push принят за 3.20 с; красный отклонён за 1.96 с;
удаление и force push запрещены. Remote protection требует public
или GitHub Pro.

**Ссылки:** [docs/PILOT.md](docs/PILOT.md),
[.github/workflows/verify.yml](.github/workflows/verify.yml).

**Ссылки:** [.gitattributes](.gitattributes), [PROCESS.md](PROCESS.md).

## 2026-10-22 · 0.7.6 · deadcode: методы

**Решение:** `cmd/deadcode` проверяет unexported-методы. Использованием
считаются селектор `x.method`, method expression и имя метода в интерфейсе;
`// deadcode:keep` — для рефлексии и `go:linkname`.

**Почему:** методы — такая же мёртвая сложность, как функции и типы.
AST уже позволяет срез без внешних зависимостей.

**Отвергли:** полный `go/types` и автоматическое доказательство
реализации интерфейсов — это следующий уровень; сейчас консервативно
сохраняем методы, чьё имя встречается в интерфейсе.

**Последствия:** возможны false positive при вызове через рефлексию —
тогда keep. Метод с тем же именем на другом типе может скрыть мёртвый
метод (false negative); это осознанный компромисс.

**Ссылки:** [cmd/deadcode/main.go](cmd/deadcode/main.go),
[cmd/deadcode/main_test.go](cmd/deadcode/main_test.go).

## 2026-10-22 · 0.7.4 · deadcode: типы, переменные, константы

## 2026-10-22 · 0.7.3 · AST-детектор мёртвого кода

**Решение:** добавили `cmd/deadcode` на `go/ast`: ищет неиспользуемые
unexported-функции, пропускает generated-файлы и `// deadcode:keep`.

рефлексии/`go:linkname` возможен false positive — тогда `// deadcode:keep`.
Типы, переменные и методы пока не проверяются.

**Ссылки:** [cmd/deadcode/main.go](cmd/deadcode/main.go),
[PROCESS.md](PROCESS.md), [verify.py](verify.py).

## 2026-10-22 · 0.7.2 · Мультистек и #render

**Решение:** `verify.py` запускает `build/test/lint/fmt` из `project.json`
для любого стека; Go-специфичные проверки (`go.mod`, размеры Go-файлов,
`gofmt`) включаются только при `stack: "go"`. Источник схемы
`project.json#render` хеширует только version/date/fonts, поэтому смена
команд не требует перерисовки.

**Почему:** шаблон нужен на всех проектах, а не только на Go. При этом
изменение команд — не изменение картинки; drift не должен быть ложным.

**Отвергли:** хардкодить Go в gate; заставлять перерисовывать схемы при
каждой правке команд; тащить npm ради не-Go проектов.

**Последствия:** не-Go проект задаёт `stack` и `commands`, фиксирует
исключение правила 4 в ADR. Запрет npm остаётся, пока `forbid_npm`
не выключен явно.

**Ссылки:** [README.md](README.md), [project.json](project.json),
[verify.py](verify.py).

## 2026-10-22 · 0.7.1 · Secret entropy, branch protection, CI-матрица

## 2026-10-22 · 0.7.0 · Release candidate: профиль, конфиг, lock и тесты

**Решение:** шаблон стал конфигурируемым: `project.json` задаёт стек,
команды, обязательные файлы и схемы; `PROJECT.md` и `FEATURE.md` —
человеческие профили; `verify.py` читает конфиг. Схемы защищены
`docs/schemes.lock.json`, gate проверяется `tests/test_verify.py`,
Go-путь — `examples/minimal-go`.

**Почему:** до этого gate был захардкожен под этот репозиторий, схемы могли
устареть молча, а генераторы зависели от Windows-шрифта. На втором проекте
пришлось бы менять сам gate — это противоречит смыслу шаблона.

**Отвергли:** редактировать `verify.py` под каждый проект; хранить
обязательные ADR по именам; считать наличие PNG достаточной проверкой схем;
тихо откатываться на дефолтный шрифт.

**Последствия:** новый проект заполняет `project.json` и `PROJECT.md`,
не трогая gate. Изменение правил или стратегии требует
`python verify.py --update-schemes`. Branch protection остаётся настройкой
репозитория, а не файлом.

**Ссылки:** [README.md](README.md), [project.json](project.json),
[tests/test_verify.py](tests/test_verify.py), [docs/schemes.lock.json](docs/schemes.lock.json).

## 2026-10-22 · 0.6.7 · Практики из продуктового чек-листа

**Решение:** взяли механику, а не числа: бюджеты «файл ≤ 400 строк,
функция ≤ 80», типизированные структуры вместо map, тесты по блокам,
бэкап с проверкой восстановления, append-only миграции. `verify.py`
проверяет размеры файлов/функций и `gofmt`, когда появится Go-код.

**Почему:** эти практики уменьшают цену ошибки и не зависят от размера
команды. Они проверяемы, поэтому не остаются лозунгами.

**Отвергли:** 900 тестов / 64 группы как KPI; 71% документации как цель;
абсолютные 80/400 без контекста; Python-специфику (ruff, dict-модели) —
её заменили `go vet`, `gofmt` и типизированные структуры.

**Последствия:** правило 6 стало измеримым, правило 10 — про восстановление
и миграции, правило 3 — про разбиение тестов. Числа-ориентиры остаются
сигналом, а не целью.

**Ссылки:** [RULES.md](RULES.md) (правила 3, 6, 10), [PROCESS.md](PROCESS.md),
[STRATEGY.md](STRATEGY.md), [verify.py](verify.py).

## 2026-10-18 · 0.6.2 · Go stdlib вместо JS/Node

**Решение:** продукт пишем на Go, только стандартная библиотека.
Сторонних модулей, npm и `node_modules` нет. ООП — структуры, интерфейсы,
композиция.

**Почему:** npm — транзитивные зависимости, регулярные обновления и CVE,
которые не зависят от нашего кода. Критерий продукта — ноль зависимостей.

**Отвергли:** JS/Node.js; Python stdlib как продуктовый рантайм;
любые сторонние пакеты.

**Последствия:** один статический бинарник; `go.mod` без `require`;
генераторы схем остаются build-time инструментами на Python/Pillow.

**Ссылки:** [docs/adr/0001-zero-dependencies-go.md](docs/adr/0001-zero-dependencies-go.md).

## 2026-10-17 · 0.5 · Десять правил и бюджет

**Решение:** держать ровно десять правил. Новое правило вбирает старое
или отклоняется.

**Почему:** иначе через месяц правил будет сорок, и их перестанут читать.

**Отвергли:** бесконечный список правил без бюджета; правила без проверки.

**Последствия:** каждое новое требование проходит через слияние с существующим
правилом; стратегия стала отдельным слоем, а не одиннадцатым правилом.

**Ссылки:** [RULES.md](RULES.md), [STRATEGY.md](STRATEGY.md).
