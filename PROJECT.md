# PROJECT: all-project-base

Профиль проекта. Для нового проекта скопируйте файл и замените значения.
Машиночитаемая часть — `project.json`; этот файл объясняет её человеку.

## Назначение

Шаблон архитектуры для проектов на Go stdlib: правила, процесс, схемы,
решения. Сам шаблон не является продуктовым сервисом; продуктовый код
появится в отдельных пакетах.

## Стек

- Go, только стандартная библиотека; `go.mod` без сторонних `require`.
- Python 3.11+ и Pillow — только build-time инструменты для `verify.py`
  и генераторов схем; в продукт не входят.
- npm, Node.js, `node_modules` не используются.

## Команды

```bash
go build -o bin/ ./...
go test ./...
go vet ./...
gofmt -l .
go run ./cmd/deadcode
go run ./cmd/deadcode -json
python verify.py
python verify.py --update-schemes
python -m unittest discover -s tests
```

## Границы

- Домен не знает про БД, HTTP и UI.
- Микроблок: файл ≤ 400 строк, функция ≤ 80, один контракт.
- Данные — типизированные структуры, не `map[string]any`.
- Глобального изменяемого состояния нет; зависимости — через конструктор
  или интерфейс.

## Данные

- Владелец данных: команда проекта.
- Миграции append-only: старые шаги не удаляются и не редактируются.
- Бэкап считается сделанным только после проверки восстановления.
- Секреты — вне кода и логов; в диффе ключей нет.

## Логи

- `tests/test.log` — только тесты; перезаписывается.
- `var/log/app.log` — только ошибки/события прода; append-only.
- `JOURNAL.md` — только решения; код и тесты в него не пишут.

## Окружения

- `local` — рабочая машина разработчика.
- `ci` — GitHub Actions, Ubuntu, Python 3.12, Go stable.
- `prod` — появляется вместе с продуктом; деплой только на зелёном `verify`.

## Исключения

- Генераторы схем — Python/Pillow, build-time; их зависимости не попадают
  в продукт.
- Другой язык продукта — только если он даёт ноль зависимостей и это
  записано в ADR.

## Пилот

- Фича: [features/0001-deadcode-json.md](features/0001-deadcode-json.md).
- CI: `github`; workflow готов.
- Branch protection: **включён** (public): PR + `verify (ubuntu-latest)` и
  `verify (windows-latest)`; force push и удаление запрещены. Локальный
  `pre-receive` gate тоже проверен.
- Метрики: [docs/PILOT.md](docs/PILOT.md).

## Локальные правила

Проектные правила и проверки добавляются сюда и в `project.json`, но не
увеличивают десять инвариантов из `RULES.md`.
